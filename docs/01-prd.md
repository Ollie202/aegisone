# Product Requirements Document

## Product

ProofRail *(working name)* — independent software artifact provenance and rebuild verification.

## Primary Wave 3 user

A developer/security-conscious user who wants to confirm that a downloaded software artifact matches an explicitly registered build of a specific source revision.

## Primary Wave 3 use case

A maintainer submits a public GitHub repository, exact commit, build recipe, and expected artifact path. The system builds the project using the supported execution path, generates provenance, stores the evidence, anchors a verification record on 0G, and exposes verification through CLI/web.

## Core user stories

### Maintainer
- I can identify an exact repository and commit.
- I can provide a deterministic build recipe.
- I can request a build.
- I can see the resulting artifact digest and evidence references.
- I can publish/register the verification record.

### Verifier
- I can inspect the source commit and provenance associated with an artifact.
- I can independently calculate the artifact digest.
- I can verify that the digest matches the registered evidence.
- I can see when an artifact fails verification.

## Wave 3 MVP scope

### Must have
- GitHub public-repository source input.
- Exact commit pinning.
- One supported build family initially: Node.js repository with pinned lockfile.
- SHA-256 artifact hashing.
- Canonical provenance manifest.
- Local verification engine.
- 0G Storage upload/retrieval of provenance.
- Minimal 0G mainnet registry.
- 0G confidential execution integration if the technical spike confirms a usable build/retrieval flow.
- CLI verification.
- Public web verification page.
- Tamper-detection demo.

### Stretch only
- GitHub Action.
- SBOM generation.
- Docker image verification.
- Direct artifact-digest binding into TEE report data.
- 0G Compute divergence diagnosis.

## Non-goals for Wave 3

- Multi-chain support.
- Token incentives.
- Builder marketplace.
- Reputation/staking.
- Arbitrary language ecosystems.
- Production enterprise IAM.
- AI chatbot.
- General malware detection.

## Success criteria

Wave 3 is successful when a third party can:

1. inspect a real public source commit;
2. inspect evidence generated by a real build;
3. retrieve/verify the stored provenance;
4. inspect a real 0G mainnet registry transaction;
5. verify the genuine artifact;
6. modify the artifact and observe deterministic failure.
